Launch one or more specialized subagents (`tasks`) concurrently in a JoinSet and wait for their structured outcomes.
- Task fields: Each item in `tasks` accepts `agent_name` (call `list_subagents` first if unsure, e.g. `"analyst"`, `"writer"`, `"reviewer"`, `"designer"`), `task` (self-contained brief with `doc_id`, `expected_revision`, assigned `block_id` prefix, verified `source_ids`, and visual anchor IDs—subagents cannot call `ask_user` or `spawn_subagents`), `display_name` (short UI card title), `section_id` (Heading `block_id` so the UI card links directly to that chapter), `model` (optional route override), and `resume_run_id` (pass a previous `subagent_run_id` to resume that subagent's persistent multi-turn conversation memory, e.g. re-invoking the same `reviewer` after fixes).
- Receipt: Returns outcomes in the exact input `tasks` order with `status` (`"completed" | "failed" | "cancelled"`), `summary`, and `subagent_run_id`. Always verify actual document changes after subagents finish.
