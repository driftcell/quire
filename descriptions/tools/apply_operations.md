Atomically apply declarative block operations (`ops`: `insert_after`, `insert_before`, `append`, `append_to_section`, `patch_block`, `replace_range`, `delete_blocks`, `move_block`) with `expected_revision` Smart CAS rebasing and optional same-transaction `sources` upserts.
- Routing & In-place rule: Always use `patch_block` to update an existing block's `text`, `level`, `title`, `note`, `source_ids`, `lint_ignore`, or table data (`columns`, `rows`, `summary_rows`, `append_rows`, `update_cell`); never replace an existing block with a new `block_id` via `replace_range` during revisions, or review comment anchors will detach (`anchor_detached: true`). For ECharts charts, use `preview_echarts` + `commit_chart` instead.
- Lock-free interleaving: Anchor prose around committed visual blocks with `insert_before` / `insert_after`, and add new H2 subsections with `append_to_section` on the parent H1.
- Receipt: Returns `new_revision`, `rebased`, `assigned_ids`, `blocking_errors` (must be fixed before proceeding), `inline_warnings`, and `_next_hint`. If a concurrent edit overlaps the same block IDs, the call fails with `REVISION_CONFLICT` and `latest_blocks`—merge into `latest_blocks` and retry.
